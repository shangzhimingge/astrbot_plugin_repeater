# astrbot_plugin_repeater — 群复读机

AstrBot 群复读机插件：当群里连续 **N 个不同的人** 发送了相同消息时，机器人自动跟一条一模一样的消息。

适用于 **NapCatQQ（OneBot v11）**，通过 AstrBot 的 `aiocqhttp` 适配器工作。

例如：群里刷屏「疯狂星期四V50」，当检测到 **3 个不同的人** 都发了这条消息（阈值可自定义），机器人就会自动跟一条「疯狂星期四V50」。

## 功能特性

- ✅ 按群独立开关复读机模式
- ✅ 自定义触发人数（默认 3，范围 2~50）
- ✅ 按「不同的人」计数：同一个人刷 10 条也只算 1 人
- ✅ 只统计**连续**发送的相同消息，内容一变自动重新计数
- ✅ 支持单段纯文本（含 Unicode 表情）、QQ 表情、图片、QQ 表情+图片链和商城动画表情
- ✅ 同一连续有效消息段只成功复读一次，内容变化后可再次触发
- ✅ 可选触发冷却时间，防止机器人刷屏
- ✅ 群设置持久化保存，重启不丢失

## 安装

### 方式一：WebUI 上传安装（推荐）

1. 将 `astrbot_plugin_repeater.zip` 上传到 AstrBot WebUI → 「插件管理」→ 上传安装；
2. 安装后重启插件或在插件管理处点击「重载」。

### 方式二：目录放置

将 `astrbot_plugin_repeater` 文件夹放入 AstrBot 的 `data/plugins/` 目录下，然后在 WebUI 中启用。

## 配置（WebUI）

在 AstrBot WebUI → 插件配置 中可修改全局默认值：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enable` | bool | `true` | 插件默认是否启用复读机模式 |
| `command_permission` | string | `bot_owner` | 子指令最低权限：`member` / `admin` / `owner` / `bot_owner` |
| `threshold` | int | `3` | 触发复读所需的不同人数（2~50） |
| `cooldown` | int | `0` | 触发后冷却秒数，`0` 表示无冷却 |
| `media_diagnostics` | bool | `false` | 将脱敏媒体轨迹提升到 Info 日志，便于现场排查 |

## 群内指令

指令前缀以 AstrBot 设置为准（默认 `/`）。
以下五个子指令统一受 `command_permission` 控制，权限从低到高为群成员、
群管理员、群主、BOT 主人；默认仅 BOT 主人可用。群管理员和群主身份读取
OneBot 群成员角色，BOT 主人身份使用 AstrBot 管理员配置判定。角色缺失或
未知时按群成员处理；配置值异常时记录警告并按 `bot_owner` 处理。

| 指令 | 说明 |
|---|---|
| `/复读机 开` | 开启本群复读机模式 |
| `/复读机 关` | 关闭本群复读机模式 |
| `/复读机 阈值 5` | 设置触发人数为 5 人 |
| `/复读机 冷却 30` | 设置触发冷却为 30 秒（0 表示无冷却） |
| `/复读机 状态` | 查看本群复读机当前状态 |

## 行为说明

- 机器人**不会**复读自己的消息，也不会把 `/复读机 ...` 指令当成复读内容；
- 优先读取 OneBot 原始消息数组中的单个 `image` / `mface`，因此 AstrBot 解析链为空时仍可复读图片和商城动画表情；
- 原始消息可包含恰好一张图片及一个或多个普通 QQ `face` 表情，并可带空白文本、回复段或仅 @ 机器人自身；复读时保持表情与图片的原始顺序；非空正文、@ 他人、两张图片或未知消息段会整条忽略；没有原始媒体时，继续回退到单个解析后纯文本、QQ 表情或图片组件；
- 「连续」指相邻有效消息内容必须相同；有效内容一变，计数清零重新开始；
- 被忽略的消息不参与计数，也不会切断当前有效消息段；
- 同一连续有效消息段成功复读后不再累计；插入不同有效消息会开始新段，因此之后相同消息可重新达到阈值并触发；
- 冷却期内发送者不计数，但不同有效消息仍会切换消息段；冷却结束后的第一条消息只计 1 人；
- 发送成功后才提交「本段已复读」和冷却时间；发送异常会记录日志，下一条相同消息可重试；
- 普通图片参考解析后组件语义，优先从 parsed `file` → `url` → `path` 选择内容探针，再使用 raw 来源回退；可信 `file_unique`、终端 MD5/SHA-256 与 UUID 继续走快速路径；
- URL（包括会变化的 `fileid` / `rkey`）、Base64、普通文件名、路径、超长或临时 opaque token 均优先经 AstrBot 转成 Base64，统一解析 bare Base64、`base64://` 与 Data URI，按解码后的真实字节计算 SHA-256；相同图片字节可跨文件名或 URL 合并计数，不同字节会切段；
- 内容探测会逐条重新读取来源，避免同一 URL 或路径在短时间内内容变化时沿用旧摘要；全部探针失败后，仅将确认稳定的短 `file` / `path` 摘要作为保守身份兜底；raw 字段主要用于识别消息结构与发送来源，仅在 parsed 图片缺失时参与身份兜底；
- 图片身份与发送来源分开处理：强身份可来自 raw 或 parsed 字段；发送与弱身份转换依次尝试 parsed 图片组件、parsed/raw 的 `url`、`path`、`file`，其中 parsed 组件按 AstrBot 的真实 `url or file` 语义处理，`path` 始终保留为独立回退；单个来源失败会用完整消息链继续尝试后续来源，首次成功即停止；
- 复读图片会新建发送组件；已经取得 Base64 时直接使用规范化 Base64 图片组件，避免复用 NapCat 入站消息级长 token；
- 商城动画表情只要存在 `emoji_id` 就以该 ID 判重，缺失时才使用 `key` 的 SHA-256；旧版 `mface` 优先经 OneBot 原生接口直发，仅在接口缺失且存在 GIF URL 时按图片发送；
- **复读消息是直接发送的**：即使 AstrBot 开启了「回复时引用发送人消息 / 回复时 @ 用户」，复读时也**不会**引用或 @ 最后一位发送者，保证纯复读效果（普通 LLM 回复的引用/@ 不受影响）。

## 常见问题

**Q：机器人完全不复读？**
A：① 检查是否已执行 `/复读机 开`；② 检查 WebUI 中插件 `enable` 配置；③ 确认 AstrBot 的适配器是 `aiocqhttp`（OneBot v11），其他适配器需自行去掉 `main.py` 中的平台过滤装饰器。

**Q：为什么复读时不引用/不 @ 最后一位发送者？**
A：AstrBot 的「回复时引用发送人消息 / 回复时 @ 用户」是在结果装饰阶段统一加上的，插件用 `event.send()` 直接发送复读消息绕过了该阶段，因此复读会原样跟一条。这是有意设计，普通 AI 回复仍会正常引用/@。

**Q：一个人刷屏会不会触发？**
A：不会。按「不同的人」计数，同一个人重复发只算 1 人。

**Q：同一张图片为什么可以稳定触发复读？**
A：NapCat 的 raw `file` / `fileid` 可能逐条变化。插件优先读取 AstrBot parsed 图片来源并按真实图片字节判重；只有内容探测全部失败时，才保守采用稳定短 `file` / `path`，并另选可发送来源重建图片组件。

**Q：如何排查媒体为什么没有计数或发送？**
A：临时开启 `media_diagnostics`，在 Info 日志中检索 `[repeater.media]`；关闭时这些轨迹只进入 Debug。正常处理和跳过路径会记录白名单化的 raw/parsed 消息类型摘要、判重策略或跳过原因、指纹短摘要、计数、实际阈值、处理结果、发送通道和异常类型；未知消息段统一显示为 `other`。日志不记录 URL、路径、`rkey`、商城表情 `key`、Base64、完整 token、正文、Face ID、群号或用户号。

**Q：想支持其他平台（如 QQ 官方、Telegram）？**
A：删除 `main.py` 中 `on_group_message` 上方的 `@filter.platform_adapter_type(...)` 一行即可（保留群聊过滤即可）。

**Q：数据存在哪里？**
A：群设置保存在 AstrBot 的 `data/astrbot_plugin_repeater/state.json`，不在插件目录内，更新/重装插件不会丢失。
